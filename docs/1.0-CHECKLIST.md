# Kairo 1.0 readiness

The 1.0 pull request is a release candidate for review. It does not publish a production build.

## Automated coverage

- JSON round-trip preserves amounts, price histories, deadlines, legacy icon IDs, categories and preferences.
- Truncated, oversized, invalid UTF-8 and unsupported backups are rejected.
- Export verification distinguishes a matching file from a failed read or changed file.
- Repeated imports preserve local edits and do not duplicate payments.
- Cross-currency imports cannot add payments to a different-currency book. Empty books adopt the imported currency.
- Verification is read-only; incompatible import previews do not offer a merge action.
- Switch rows expose their label, state and action together. Required fields expose inline errors and focus after Save.
- Existing billing, reminders, widgets, categories, large-text entry and theme tests remain required.

## Device checks before publication

- [ ] Export to your usual document provider, verify the saved file, then merge it into the separate dev/prod installation and compare payments and history.
- [ ] Restore through Android backup/device transfer and check payments, app settings and widget setup. CI cannot verify your Google backup account or device restore.
- [ ] Use TalkBack on Overview, Payments, Calendar, Insights, payment entry and Settings; check traversal order and switch labels.
- [ ] Review at large font/display sizes in both themes, with the keyboard open; check the custom-payment FAB and calendar navigation.
- [ ] Check trial and renewal notifications with the app closed, including snooze and a scheduled price change.
- [ ] Keep the existing production signing key and run the production workflow only after review and merge.
